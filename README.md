# 算法可视化 · Algo Viz

把算法的执行过程画成动画，旁边再配一套 C++ 语法和 STL 的入门教程。

当初做它是因为自己学排序的时候，看伪代码只看到 `for i = 0 to n-1`，看动画才真的记住数据是怎么动的。
后来发现看懂动画不等于读懂代码，就又补了第二个页签：算法里用到的那几个语法点单独讲清楚，每段示例都配一道洛谷的原题练手。

**在线体验：** https://huy0011.github.io/algorithm/

纯静态页面，没有依赖也没有构建步骤，clone 下来起个服务器就能跑。

---

## 里面有什么

**算法可视化** —— 32 个算法和数据结构，分成排序、查找、寻路、基础技巧、字符串、位运算、高精度、图论等 10 类，每一类有自己的画法。

![算法可视化](docs/screenshot.png)

**C++ 语法 / STL** —— 35 个知识点，从 Hello World 一直到 `priority_queue`。每个知识点是一段完整可编译的代码 + 关键点 + 洛谷练习题。

![C++ 语法](docs/screenshot-syntax.png)

两个页签能互相跳。算法下面列着它用到的语法点，点一下过去看；语法点底部列着用它的算法，点一下回来看动画。哪行代码没看懂，点它就行。

> 两张截图是用点阵字体合成的，所以文字是英文，实际页面是中文。

## 关于 C++ 示例的输出

浏览器跑不了 C++，站点又放在纯静态的 GitHub Pages 上，所以没法做到「在网页上改一行再重跑」。

这里的做法是构建时用 g++ 把每个示例编译运行一遍，把真实输出存进 `src/syntax/cpp-output.js`，页面直接读。所以你看到的输出确实跑过，不是手打的；但页面上也不能重新编译，想改代码得复制到本地或在线编译器。

## 本地运行

用了 ES Modules，`file://` 打不开，需要一个本地服务器：

```bash
node tests/serve.js        # 自带的小服务器，然后打开 http://localhost:5173
# 或者
python -m http.server 5173
```

需要 Node 18+，但不用 `npm install`。

```bash
npm test        # 全部测试
npm run audit   # 静态审计：死代码、可访问性、SEO、文档同步
npm start       # 同 node tests/serve.js
```

改了 C++ 示例的话，用 `node tests/build-cpp.js` 重新生成源文件，编译运行完再 `--collect` 收集输出，具体步骤在脚本头上。

## 一点设计说明

算法层不知道什么叫画布、颜色、DOM，它跑完只交出一串「发生了什么」：比较了哪两个位置、交换了、写入了一个值、标记了哪些格子。渲染层拿着这串记录照着画。

这么拆的好处是加算法基本不用碰渲染代码，进度随便跳也不会有状态不同步的问题，换个画法只要渲染层认识那些操作就行。测试里有一条静态检查专门守着这个边界，防止哪天有人顺手在算法里写一句 `document.querySelector`。
